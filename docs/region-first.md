# 地点から始める（駅からではなく）

開発指示書「地域診断エンジン」§1〜§10 への実装。

---

## 1. 何が起きていたか

```
地点 → 最寄り駅 → 駅の属性 → 地域の説明
```

**駅から書き始めると、駅の性格が地域の性格として語られます。**

実測：沼津駅の南南西 810m（徒歩10分）の候補地が、駅前の分析になっていました。
レポートの最初の節が「この候補地そのものについて」で、その 1 行目が最寄り駅
だったからです。周辺スキャンのプロンプトも駅の方角から始まっていて、検索も
駅名から始まっていました。**候補地が駅から 800m 離れていても、同じ結果が
返ってきます。**

---

## 2. 変えた順番

```
地点
　↓
周囲の実態（500m / 1km / 2km の集計と、比較母集団の中での位置）
　↓
地域の構造（指標どうしのアンバランス、足元と周りの差）
　↓
必要な場合だけ、駅・商業施設・病院などを説明変数として足す
```

レポートの節も、そのとおりに並べ替えました（指示書 §8）。

| | 節 | 中身 | 誰が書くか |
|---|---|---|---|
| 1 | この地域はどんな場所か | 1 文の定義 + 地域特性タグ（根拠つき） | **計算** |
| 2 | 地域を構成する主な特徴 | 軸ごとの位置 + 500m/1km/2km の階層 | **計算** |
| 3 | 周辺地域と比較した特徴 | アンバランス + 足元と周りの差 | **計算** |
| 4 | この候補地と駅の関係 | 距離の区分 + 人口が駅側に寄っているか | **計算** |
| 5 | この分析で確かめたこと | 問い・仮説・未確認 | 計算 |
| 6〜 | 結論・需要・将来・開業への意味 | 散文 | LLM |

**駅は 4 番目です。** 地域の姿が決まったあとに、それを説明する要素として
出てきます。

## 3. 地域特性タグ（§4）

**個別指標を LLM に解釈させる前に、システム側で特徴を抽出します。**

「人口が上位8%、歯科医院が上位35%」を読んで「人口集積地域だが供給は薄い」と
言うのは、これまで LLM の仕事でした。**それは解釈であって Fact ではありません。**

```
| 特徴          | そう判定した根拠           | この特徴が意味すること           |
| 人口希薄型     | population_mass が 0%     | 住んでいる人が少ないほうに入る    |
| 医療供給過密型  | supply が 100%            | 人口あたりの歯科医院が多いほうに  |
| 駅との関係弱   | 駅からの距離の区分が「駅近隣」 | 駅の日常動線からは外れた立地      |
```

ルールは `config/dental_clinic/positioning.yaml` の `tags`。条件に書けるのは
`axis` / `gap` / `station_band_in` / `station_side_*` の 4 種類だけです。

**複数付きます。**「人口集積型」かつ「医療供給過密型」かつ「将来人口減少型」は
矛盾ではなく、その地域の実態です。ひとつに絞ると、絞った時点で解釈になります。

**確かめられない条件のタグは付けません。**「条件を満たさなかった」と
「確かめていない」は別のことなので、無いことを根拠にしません。

タグは `positioning.tag.*` として引けます。**引けないと LLM は言い直すしか
なく、言い直した瞬間に「その判定はどこから来たのか」が辿れなくなります。**

## 4. 駅の扱い（§6）

### 4.1 距離の区分

指示書の区分に合わせました。**812m の地点を「駅前」と表現しません。**

| 距離 | 呼び方 |
|---|---|
| 〜300m | 駅前 |
| 〜800m | 駅徒歩圏 |
| 〜1200m | **駅近隣**（810m はここ） |
| 1200m超 | 駅との関係弱 |

### 4.2 距離だけでは決めません

**駅まで 800m でも、人が全員反対側に住んでいるなら、駅は来院動線では
ありません。** 逆に 1km でも、駅との間に住宅が詰まっているなら関係はあります。

候補地からメッシュ重心への方位を出し、駅の方角 ±90 度に入るものを「駅の側」
として合計します。

```
- **商圏人口の 20% が駅の側**（駅の方角±90度。駅側 200 人 / 反対側 800 人）
  　商圏の人口は駅と**反対側**に寄っています。駅までの距離が近くても、
  　住民の動線は駅を向いていない可能性があります。
```

「駅依存度高型」のタグは、**距離と方向の両方**が揃ったときだけ付きます。

## 5. 階層（§2）

候補地を中心に、外へ広げます。

```
|            | 人口  | 歯科医院 | 面積の比 | 人口の比 |
| 半径 500m   |   299 |        2 |     —   |     —   |
| 半径 1,000m | 1,167 |        5 |   4.0倍 |  3.91倍 |
| 半径 2,000m | 2,716 |       24 |   4.0倍 |  2.33倍 |
```

**合計だけを並べると、外側が大きいのは当たり前です。** 面積の比と並べて初めて
「どこで増えたか」が読めます。上の例では、人口は 1km→2km で薄くなる一方、
**歯科医院は 5 → 24 に増えています。** 医院の集積は 1〜2km の外側にある、
という話で、**半径ひとつだけを見ていたら出てきません。**

## 6. LLM の役割（§9）

変わっていません。**LLM は Fact を作りません。**

```
GIS / Python / SQL   →  数値計算・比較・タグ付与
LLM                  →  タグと Fact の文章化・意思決定への接続
```

今回足したのは、LLM に**渡すもの**です。タグ・階層・駅との関係は全部計算済みで、
プロンプトは「タグを作り直したり、条件を読み替えたりしないでください」と
言っています。

**1 文の地域定義（§7）は、LLM 無しでも出ます。** タグを並べれば文になります
——「人口希薄型・医療供給過密型・駅との関係弱の地域です。」 LLM にはより
読みやすい 1 文を書かせますが、**それが落ちてもレポートの冒頭は空になりません。**

## 7. まだのもの

- **§2 の市区町村・周辺自治体の階層。** 比較母集団としては既にあります
  （`municipality` / `neighbourhood`）が、階層の表には入れていません。
  半径の円と行政界は別の形なので、同じ表に並べると読み手が混同します。
- **§6 の道路・徒歩ネットワーク距離。** 直線距離で区分しています。徒歩圏
  （街路網）は実装済み（`catchment=walk`）なので、駅までの経路距離に
  差し替えられます。**川や線路を挟むと直線距離は嘘をつきます。**
- **§4 の「若年層希薄型」「住宅地域型」「商業地域型」。** 年齢構成と用途地域は
  データにありますが、軸にしていないのでタグの条件に書けません。軸を足すのが
  先です。
