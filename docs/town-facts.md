# この街、どんな街？（街の意外な事実）

## 何をする画面か

駅名か市区町村名を 1 つ入れると、**その街の意外なところ**が数枚のカードで
返ります（`/town`）。地図を操作してもらうための画面ではありません。詳しく
見たくなった人だけが地図へ行きます。

    この街、どんな街？   [ 東京 ]  → 調べる

    1  似た街と比べて     同規模の街と比べると、従業者数が際立って多い街
       従業者数 565,420人（同規模の中央値 154,708人）
       乗降客数が同規模の駅：北千住・品川・高田馬場・池袋・新宿 と比べて +265.5%

    2  この街の水準       地価が高い街
       地価（公示・中央値）21,200,000円/m²
       東京都の半径1000m商圏 4,708件の中で上位0.1%（1位）／中央値 445,000

## 数えるのは Python、驚くのは読み手

**新しい数字を作りません。** カードの材料は、データセットが既に確定させた
比較です。

| 材料 | どこから | カードの種類 |
|---|---|---|
| percentile・順位 | `measures`（都道府県の分布） | `level` この街の水準 |
| 軸どうしのズレ | `positioning.gaps` | `contrast` ちぐはぐなところ |
| 同規模の街との差 | `peers.standouts` | `peers` 似た街と比べて |

`town.py` がするのは、**離れているものを選んで並べ替えること**だけです。
だから同じ地点なら何度引いても同じカードが出ます。LLM も外部 API も
呼びません。1 地点あたり 1.8 秒ほど。

## 「意外」を作るために事実を曲げない

カードは**常に 5 枚出せます。** 出すために母数 30 件の「上位10%」を混ぜても、
取り込んでいない県の分布で語っても、**画面は成立します。** だから 4 つ守ります。

**根拠が弱いものは出さない。** 確からしさを母集団の大きさから数にして
（1,000件以上=0.95／200件以上=0.85／30件以上=0.7）、`min_confidence` で
落とします。30 件の中の「上位10%」は 3 位というだけのことで、分布では
ありません。弁別力のない母集団（半分が無人メッシュ）も同じく落とします。

**同じ話題で埋めない。** 人口の話が 5 枚並ぶのは「5 つの発見」ではありません
（`max_per_theme`、既定 1）。話題が尽きたら 5 枚に満たなくても構いません
——「7 件の比較から 4 件を選びました」と画面に出ます。

**「平均的でした」はカードにしない。** 閾値（既定：上位10%／下位10%）を
超えたものだけが候補です。

**出せない比較は、出せないと書く。** 全国順位が無いのは「意味がないから」
ではなく「全国のメッシュを取り込んでいないから」です。読み手にはその区別が
つきません。画面の下に「この街について、まだ言えないこと」として出します。

## 取り込んでいない土地を、別の県の分布で語らない

実測：メッシュが東京都だけの環境で「沼津」を引くと、県が特定できず既定
（人口最大の県＝東京都）に落ち、**沼津駅のカードに湯島・高井戸・氷川台が
並びました。** 分析としては動いていて、画面も成立します——読み手だけが
気づけません。

`/api/town` は地点の県が特定できないときに分析へ進まず、こう返します。

    沼津駅の分析：この地点の周辺には、取り込み済みの人口メッシュがありません。
    いま比較できるのは東京都です。

## 同じ名前の別の街

「府中」は東京にも広島にもあります。名前で引いたときは**何に当たったかと、
他の候補**を返し、画面はそれを押せるようにしています。黙って 1 つ選ぶと、
読み手は別の街の話を自分の街の話として読みます。

これは KPI の導線でもあります。この画面が目指すのは GIS を操作してもらう
ことではなく、**「もう一つ別の街も調べてみたい」と思わせること**です。

## 縮尺

街の話は**半径 1km** で見ます（`TOWN_RADIUS_M`）。業態の既定（歯科は 500m）は
開業候補地を見るための半径で、街を語るには小さすぎます。比較相手のメッシュ
分布も 1km で作ってあるので、ここをそろえると本文と比較の半径が食い違いません。

## 設定

`config/town_facts.yaml`。**しきい値と見出しはここ、数え方はコード。**

    count            出す枚数（既定 5）
    max_per_theme    同じ話題の上限（既定 1）
    min_confidence   これ未満は出さない（既定 0.7）
    theme_weight     対比を少し重く（level 1.0 / peers 1.2 / contrast 1.4）
    metrics          指標ごとの閾値と見出し（at_least / at_most / high / low / why）
    gaps             軸のズレの見出し
    peers            同規模の街と比べたときの見出し
    unavailable      固定で書いておく「出せない比較」

`metrics[].key` は `measures.MEASURE_SPECS` の指標名です。無い名前を書くと
`UnknownTownMetric` で落ちます。黙って無視すると、**その指標は永久にカードに
なりません**——しかも画面は成立して見えます。

日本語の長い文は YAML の折り返しを使わず 1 行で書いてください。折り返すと、
**文の途中に空白が入って画面に出ます**（「入口の 指標です」）。

## いま入れていないもの

**LLM による文章化。** 指示書は「Python が値を出し、LLM が面白い事実に
文章化する」構成ですが、いまの見出しは設定のテンプレートから作っています。

そうした理由は 2 つです。1 つは費用——検索する街ごとに毎回 API を叩くと、
この製品でいちばん軽いはずの画面がいちばん高くつきます。もう 1 つは再現性で、
同じ街を 2 回引いて違う文が出ると、読み手は数字のほうも疑います。

カードの JSON は指示書の形（`title` / `fact` / `comparison` /
`why_interesting` / `source` / `confidence`）のままなので、**文章化の段を
足すときは、この JSON を渡して `title` と `why_interesting` だけ書き直させる**
のが最小の改修です。数値・比較・出典は Python 側のまま動かさないこと。
