# 地域の位置づけ — GIS が Fact を確定し、LLM が解釈する

開発指示書「地域ベンチマーク・評価エンジン」§7・§9・§14・§16・§17・§19。

---

## 1. 何が抜けていたか

```
人口：       市街地 上位 8%
歯科医院数： 市街地 上位 35%
```

この 2 行から

> 人口規模に対して歯科医院が相対的に少ない

を読み取るのは、**これまで LLM の仕事でした。**

引き算です。誰がやっても同じ答えが出ます。ところが LLM にやらせると、それは
計算結果ではなく**モデルの発言**になります。レポートを読んだ人は、それが
引き算なのか印象なのかを区別できません。**検算できない文が 1 つ増えます。**

問いの立て方や仮説検証を作り込むうちに、ここが薄まっていました。

---

## 2. 分業

```
PostGIS / SQL          →   確定した Fact
　　（値・単位・出典・比較母集団・percentile・指標どうしの差）
　　↓
LLM                    →   その Fact の意味・組み合わせ・そこから出る問い
```

**LLM は数字を作りません。** 引きます。引いた数字は `verify_step1` が実在を
確かめます。

これが「地域について書ける生成 AI」との違いです。**文章の巧さで差はつきません。
差がつくのは、書いてあることが確かめられるかどうかです。**

---

## 3. 何を計算するようにしたか

`server/kaigyou_core/positioning.py`。LLM は呼びません。しきい値も軸も文言も
`config/<業態>/positioning.yaml` にあります（**重みをコードに書かない**）。

### 3.1 母集団を 1 つに揃える

**percentile どうしを引き算してよいのは、同じ母集団のときだけです。** 人口を
市街地の中で、医院数を県内全メッシュの中で見て引くと、**意味のない数字が
それらしい顔で出ます。**

`prefer_scopes` の上から順に、使える最初のものを 1 つ選びます。

```yaml
prefer_scopes: [urban, neighbourhood, station_front, nearby, with_clinics, prefecture]
```

市街地（`urban`）を先に見るのは、県内全メッシュで語ると町の中心はどこでも
上位数%に入るからです。それは「市街地かどうか」を測っているだけで、開業地の
比較になりません。`discriminating` でない母集団は使いません。

### 3.2 評価軸（ランキング → 評価、§14）

| 観点 | 位置（0〜100） | 評価 | この数字が意味すること |
|---|---|---|---|
| 人口集積 | 96 | 非常に高い | そこに住んでいる人の多さ |
| 昼間流入 | — | **未確認** | 従業者数の分布が取れないため |
| 歯科の供給 | 78 | 高い | 人口あたりの歯科医院の多さ |

**取れなかった軸を 0 点にしません。** 0 として扱うと、データが無いことが
「低い」になります。行としては残します——落とすと「その観点では特筆すべき
ことが無かった」に見えます。

### 3.3 アンバランス（§7・§11）

同じ母集団の percentile を引き、しきい値（既定 20 ポイント）を超えたものだけ
「アンバランス」と言います。**しきい値に届かなかった組み合わせも返します**——
「調べたが差は無かった」と「見ていない」は別のことです。

### 3.4 地域タイプ（§9）

**名称を LLM に決めさせません。** 定量的なルールで決め、LLM の仕事はそれを
文章にすることです。どれにも当てはまらなければ「型に当てはまらない」と言います
——**無理に名前を付けません。** 付けた名前は、そのあと読み手の頭の中で事実と
して働きます。

### 3.5 引用できる形にする

```
positioning.axis.population_mass   = 96      （人口集積の位置づけ）
positioning.gap.demand_vs_supply   = 57.0    （需要と供給の差・ポイント）
```

**ここを通さないと、LLM はこの計算結果を引用できません。** 引用できない数字は
言い直すしかなく、言い直した瞬間に検算できなくなります。

層（`layer`）は**元の指標のもの**を使います。`positioning` という層を新設
しません。新設すると、ギャップを 2 つ引いた PATTERN が「層を跨いだ」と判定
されます。**跨いでいるのは同じ構造を 2 回言い換えただけ**で、そこを見張る
ために層の検算があります。

## 4. レポートに出る形

本文（LLM が書く部分）より**前**に入ります。あとに置くと、文章を信じたあとで
根拠を照合することになります。

```
## この地域はどんな場所か

**この節は生成された文章ではありません。**下の数値は GIS が計算したもので、
本文の記述はこれを解釈したものです。

### 類型：住宅集積型

### 位置づけ
（軸の表）

### 指標どうしのバランス
- **人口規模に対して、歯科医院が相対的に少ない**
  商圏人口 92% 対 医院数 35%（差 57 ポイント）
  　医院数は施設の数で、ユニット数でも診療実績でもありません。

調べたが、差が小さかった組み合わせ：いまと将来（差 12 ポイント）

**比較できなかった組み合わせ**（見ていないという意味です）：
- 住む人と働きに来る人：従業者数の分布が取れませんでした。

**この評価の前提**
- 比較した母集団：静岡県内で人口が生活圏規模に達する商圏（1,016 商圏）
- 評価ロジックの版：v1.0　計算日：2026-09-02
```

**どれと比べたのか・いつ・どの版か**を必ず書きます（§16・§19）。書かずに
「上位8%」とだけ言えば、それはもう統計ではありません。

## 5. 実装中に踏んだもの

**`Benchmark.percentile` は 0〜100（%）です。** 0〜1 だと思って書いたら、
軸の点が **9560** になり、しきい値 0.20 は 100 点満点の 0.2 ポイントとして
働いて、**どんな差でも「アンバランス」と判定されました。** 例外は出ません。
それらしい数字が出つづけます。単位の取り違えはいつもこの形で現れます。

## 6. まだ実装していないもの

指示書のうち、まだのもの。

- **§8 地域特徴ベクトル / §13 類似地域。** 軸の percentile が揃ったので材料は
  できました。類似地域は「どの軸で似ているか」を決めないと、似ていない地域が
  似ていることになります。距離の定義を決めてから。
- **§15 の画面。** レポートには入りました。地図画面の上に「この地域はどんな
  場所か」を出すのは次です。**データはもう `/api/dataset` に入っています。**
- **§18 の保存。** いまは呼ばれるたびに計算します。ジョブの `base_data` には
  スナップショットとして残るので、レポートの再現性はあります。メッシュごとに
  事前計算して貯めるのは、類似地域検索を作るときに一緒に。
