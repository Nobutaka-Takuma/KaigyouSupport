# 使う量を絞る（節約モード）

分析 1 回の API 費用が問題になったときの、絞り方と戻し方。

## いまの状態を見る

```
python -m kaigyou_etl analyze --budget
```

**API は叩きません。** 設定から「最悪いくらか」を計算するだけです。

```
モデル claude-sonnet-5 / 節約設定 mvp
  ※ 節約中です。分析の質は本来のものより落ちます。

  周辺一般の分析     呼び出し 6 回 / Web検索 2 回   最悪 $0.49
  周辺の競合（2 院）  呼び出し 5 回 / Web検索 2 回   最悪 $0.33
  両方を 1 回ずつ走らせて、最悪 $0.82
```

見積もりであって実測ではありません。**実際にはこれより安く済みます**——思考が
短く終われば出力は天井まで届かず、検索も上限まで使うとは限りません。見たいのは
「最悪でいくらか」で、料金が尽きるのは最悪が続いたときだからです。

## 切り替える

`config/analysis.yaml`：

```yaml
budget:
  mode: mvp     # 消す（または存在しない名前にする）と本来の設定に戻ります
  mvp:
    effort: low
    max_tokens: 6000
    ...
```

環境変数のほうが強いので、ファイルを触らずに切り替えられます。

```
KAIGYOU_BUDGET_MODE=      # 空 = 節約しない（本来の設定）
KAIGYOU_BUDGET_MODE=mvp   # mvp を使う
```

テストは常に**節約なし**で走ります（`server/tests/conftest.py`）。見たいのは
「判断の段は effort を削らない」「2 周調べる」といった、この製品が守ると決めた
ことのほうで、そこが赤くなったときに「設計が壊れた」と「節約中だから」を
区別できなくなるからです。

## 重ねる、書き換えない

節約設定は**上から重ねます。** 段ごとの設定も業態の設定ファイルも書き換えません。

```
config/analysis.yaml  steps.3.effort: high     ← ファイルはそのまま
                      budget.mvp.effort: low   ← 効くのはこちら
```

書き換えてしまうと元の値がどこにも残らず、「元に戻す」が手作業になります。
`competitors.yaml` の `max_competitors: 12` もファイル上はそのままで、効いて
いる値だけが 2 になります（`analyze --budget` に出るのは効いている値です）。

**効く項目は決まっています。** budget の下に何を書いても効く作りにすると、
打ち間違えた項目が黙って無視され、節約したつもりで満額請求されます。知らない
項目があれば `UnknownBudgetKey` で落ちます——起動時に分かるほうがよい。

## 何がいくら効くか

Claude Sonnet 5 は入力 $2 / 出力 $10（100万トークンあたり）。**出力が 5 倍**
なので、出力を削るのがいちばん効きます。

| 項目 | 本来 | mvp | なぜ効くか |
|---|---|---|---|
| `effort` | high | low | **思考のトークンは出力として課金されます。** ここが最大 |
| `max_tokens` | 64,000 | 6,000 | 最悪値の天井。届かなければ請求はされません |
| 検索（周辺一般） | 10 回 | 2 回 | 検索結果は文脈に入り、同じ呼び出しの以降のやりとりで毎回読み直されます |
| `research_rounds` | 2 | 1 | STEP2 まるごと 1 回ぶん |
| 競合の院数 | 12 | 2 | 1 院 = 2 呼び出し。12 院なら 24 呼び出し |
| 1 院あたりの検索 | 2 | 1 | 医院名＋地名だけ。公式サイトの中身は追いません |

実測（`analyze --budget`）：**最悪 $22.28 → $0.82**、27 分の 1。

## やっていないこと

**モデルは下げていません。** `claude-sonnet-5` のままです。Haiku 4.5 なら
入力 $1 / 出力 $5 で半額ですが、モデルを落とすのは分析の質そのものを変える
判断で、費用の話とは別に決めるべきものです。下げるなら
`config/analysis.yaml` の `model.id` を `claude-haiku-4-5` にします
（`budget.py` の `PRICES` に単価が入っているので、見積もりもそのまま出ます）。

**プロンプトのキャッシュは元から効いています。** system プロンプトに
`cache_control` が付いていて、2 回目以降は 1/10 の単価です。節約設定とは
無関係に効くので、ここは削るところがありません。

## 戻すとき

```yaml
budget:
  # mode: mvp        ← コメントアウトするだけ
```

`analyze --budget` で、戻ったことを確かめられます。
