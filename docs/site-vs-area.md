# その地点の分析か、その一帯の分析か

---

## 1. 何が起きていたか

沼津駅の南南西、直線で約 810m の候補地を分析したら、**駅前の分析**になって
いました。徒歩でおよそ 10 分です。駅前ではありません。

原因は 2 つあり、どちらも同じ形をしています——**測ってあるのに、判定を
モデルに任せていた。**

### 1.1 半径 1km が既定だった

半径 1km の円は **3.14km²**。駅から 810m 離れた候補地を中心に置いても、
円は駅も駅前商店街も飲み込みます。出てくるのは「その地点の分析」ではなく
**「その一帯の分析」**で、候補地を 300m 動かしても同じ結論が出ます。

歯科医院は小規模事業です。徒歩とママチャリで来る範囲が主戦場で、
半径 500m（**0.79km²**、徒歩6分）のほうが商売の実態に合います。

### 1.2 「駅前」をモデルが決めていた

`station_distance_m` は測ってあります。それなのに立地類型の選択肢に「駅前」が
あり、モデルが周辺スキャンの本文を読んで選んでいました。**810m でも「駅前」と
書けてしまいます。**

## 2. 直したこと

### 2.1 既定を 500m に（業態ごとに設定可能）

```yaml
# config/dental_clinic/insights.yaml
catchment:
  default_radius_m: 500
  compare_radius_m: 1000
```

**コードに定数を置きません。** 歯科医院と総合病院と大型店では、商圏の広さが
桁で違います。API で `radius` を省略すると、その業態の既定になります。

### 2.2 「駅前」は距離で決まる

立地類型の選択肢から「駅前」を外しました。類型が答えるのは**どんな性格の
場所か**（住宅地の路面／商業地の路面／商業施設内・隣接／オフィス街／
郊外ロードサイド）で、それは駅からの距離とは**別のこと**です——駅から 200m の
住宅地の路面もあれば、駅から 2km のロードサイドもあります。

駅からの距離は、測った値から機械的に区分します（分速 80m）。

| 距離 | 呼び方 | |
|---|---|---|
| 〜150m | 駅前 | 駅の目の前。ロータリー・駅ビルの範囲 |
| 〜400m | 駅近 | 徒歩5分 |
| 〜1000m | **駅徒歩圏** | 徒歩12分まで。**駅は使えるが、駅前ではない** |
| 〜2000m | 駅から離れた立地 | 徒歩25分まで |
| それ以上 | 駅は徒歩圏外 | 来院は徒歩以外の手段が前提 |

**沼津の 810m はここに入ります。** レポートには
「**駅徒歩圏**　最寄り駅まで 810m、徒歩約 10 分。駅から見て南南西」と出ます。

> 比較母集団の `station_front_m: 800` とは別物です。あちらは「県内のどの
> メッシュを駅前の商圏として並べるか」で、候補地そのものの話ではありません。
> 混ざっていたのが、そもそもの間違いのもとでした。

### 2.3 足元と、その周りを突き合わせる

**これが今回いちばん効いたものです。** 半径を小さくするだけでは、
「その地点そのもの」は見えません。**2 つの円を比べて初めて見えます。**

面積比は 500²/1000² = **0.25**。人が一様に住んでいれば、500m 圏には 1km 圏の
25% がいるはずです。実際の割合をこれで割ったものを**集中度**とします。

```
### 足元と、その周り

半径 500m（商圏）と半径 1000m を突き合わせたものです。
人が一様に分布していれば、内側には外側の 25% が入るはずです。

|            | 半径500m | 半径1000m | 割合  | 集中度 |
| 人口        |      299 |     1,167 | 25.6% |  1.02 |
| 歯科医院数   |        2 |         5 | 40.0% |  1.60 |

- **人口**：候補地の周りは、ほぼ一様な密度です。
- **歯科医院数**：候補地そのものが密集の中心にあります。
```

**この 2 行の差が、円を大きくすると消えます。** 人は一様なのに、競合はこの
足元に寄っている——半径 1km だけを見ていたら「医院 5 院」で終わっていました。

読み方：

- **1.00 付近** … 候補地の周りは一様。円を大きくしても小さくても同じ話
- **1.00 より大** … 候補地そのものが密集の中心にある
- **1.00 より小** … 密集は円のどこかにあるが、**候補地の足元ではない**

境目は 0.85 / 1.15 です。**狭くしすぎていません**——メッシュ統計は面積按分
なので、境目あたりの揺れはメッシュの切れ目で簡単に出ます。

## 3. 500m にすると精度が上がる、わけではない

**半径を小さくしても、統計の解像度は上がりません。** 上がるのは
「円が駅を飲み込まなくなる」ことだけです。

| 半径 | メッシュ | 面積換算 |
|---|---|---|
| 500m | 500m メッシュ | 3.1 個ぶん |
| 500m | **1km メッシュ** | **0.8 個ぶん** |
| 1000m | 1km メッシュ | 3.1 個ぶん |

**1km メッシュしか取り込んでいない県で半径 500m を測ると、面積換算で
1 メッシュ分もありません。** 値は面積按分で出ますが、それは「メッシュの中では
人が一様に住んでいる」と仮定した数字です。半分が公園で半分が団地のメッシュ
では、その仮定は外れます。

黙って出すと、細かい半径を指定したぶんだけ精密になったように見えます。
だからレポートに注意が出ます。

> 商圏（半径500m）は1000mメッシュ0.8個ぶんの広さしかありません。人口は
> メッシュとの面積按分で出していて、**メッシュの中では人が一様に住んでいると
> 仮定しています。**

**500m を既定にするなら、500m メッシュを取り込んでください。**

## 4. ピンポイントで見るなら、次は何か

いまの構成で答えられないもの。

- **建物単位。** ピンは座標で、区画ではありません。商業施設の敷地の中なのか、
  隣接する別区画なのかは判定していません（`misreadings.pin_as_parcel`）。
  街区レベル位置参照情報を取り込めば、ここは詰められます。
- **道路の向こう側。** 半径 500m の円でも、幹線道路や線路の反対側は含みます。
  「商圏の形」を徒歩圏（街路網）に切り替えると、街路に沿った範囲になります
  ——**すでに実装済みです**（`catchment=walk`）。500m の徒歩圏なら計算も軽い
  ので、既定にする価値があります。次に測ります。
- **視認性・動線。** 角地か、上り坂か、駅からの帰り道の側か。現地でしか
  分かりません。**それは失敗ではなく、この調査の結論の一部です。**
