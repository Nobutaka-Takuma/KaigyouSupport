直前の調査結果を、指定された JSON スキーマに写してください。

**これは書き写す作業です。新しい事実を足さないでください。**

## EXTERNAL FACT に書けるもの

**外部資料がその地域について述べていること**だけです。肯定文で書けないものは
EXTERNAL FACT ではありません。

良い例：「中央区の世帯数は平成26年の約9.6万世帯から平成31年に92,674世帯へ増加した」
　　　　「分譲マンションの棟数構成比は日本橋地域48.4%、京橋地域34.3%である」

**悪い例（これらは `unanswered` に書いてください）**：
- 「歯科医師会の検索サイトは医院リストであり、患者の居住地別内訳を示す統計ではない」
- 「区市町村別診療所統計に、患者の通勤圏内受診率に関する項目はない」
- 「自由診療比率などの経営指標は非公開である」

これらは**資料に何が無かったか**の記述です。調べた記録としては大事ですが、
商圏についての事実ではありません。EXTERNAL FACT に混ぜると、あとのステップが
「外部情報で12件確認できた」と読み、実際には半分が空振りだったことが見えなく
なります。

## HYPOTHESIS に書けるもの

**この特徴がなぜ存在するのかの説明**だけです。

良い例：「中央区内で人口増加率が特に高いエリアは晴海地区であり、選手村跡地の
　　　　住宅転用が背景にある」

**悪い例**：「銀座就業者の通勤圏内受診率に関する統計データが存在する」
これは資料の有無についての仮説であって、銀座についての仮説ではありません。
確認できなかったのなら `unanswered` に書いてください。

### `changes` と `decision_impact`

**仮説ごとに必須です。** 調査結果の本文に「変わるもの」が書かれているはず
なので、そこから写してください。書かれていなければ、その仮説について本文が
何を言っていたかを読み、次の6つのどれが動くのかを選んでください。

```
診療コンセプト / 設備投資 / 診療時間 / 人員体制 / 立地判断 / 患者層
```

`decision_impact` は「**AではなくBにする**」の形で 1〜2 文。「〜する余地が
ある」「〜を検討できる」は何も決めていないので、それだけでは足りません。

**仮説文をそのまま写さないでください。** 「区画整理で計画的に形成された
市街地である」に対して「計画的に形成された市街地であることが分かる」と
書いても、次の一手は動きません。機械的に照合して落とします。

正しくても6つのどれも動かない仮説は、**仮説として出さないでください。**
`unanswered` に論点として書くか、落としてください。

### status の意味

- `SUPPORTED` … 外部情報がその説明を裏付けた
- `PARTIALLY_SUPPORTED` … 一部は裏付けられたが、直接の証拠までは届かなかった
- `UNCERTAIN` … **調べたが、どちらとも言えなかった**
- `CONTRADICTED` … **調べたら、違うと分かった**

`UNCERTAIN` と `CONTRADICTED` を分けているのは、**経営判断にとってこの 2 つが
正反対だから**です。

- `UNCERTAIN` → まだ分からない。**開業前に現地で確かめる項目**になります。
- `CONTRADICTED` → その筋は消えた。**別の説明を追う**ことになります。

同じ札に入れると、レポートを読んだ歯科医師はどちらなのか判断できません。

`UNSUPPORTED` は使わないでください（古い判定です）。

**`UNCERTAIN` は積極的に使ってください。** 根拠が 1 件も無くてよい唯一の判定
です。調べて何も出なかった仮説を消すと、「調べていない」のと区別がつかなく
なります。**残してください。**

### `question_id` — どの問いに答えたか

各仮説には、答えようとした問いの id（`Q001` など）を付けてください。入力の
`questions` にある id だけです。

**答えの出なかった問いは `open_questions` に書いてください。**

```
question_id           答えの出なかった問いの id
why                   なぜ外部情報からは答えが出なかったのか
what_would_settle_it  何があれば決着するのか
```

`what_would_settle_it` は、**実際に取れる手段**で書いてください。
「さらなる調査が必要」は手段ではありません。

- 良い例：「平日18時台に現地で、駅から候補地方向への歩行者数を数える」
- 良い例：「市の都市計画課に、誘導施設に医療が含まれるかを照会する」
- 良い例：「この校地の学部構成を大学の入試要項で確認する」

### `evidence_links` — 根拠の向き

根拠にした外部事実は、**支持か反証かを付けて**ください。

```
fact_id   external_facts[].id
stance    supports    … その仮説を支持する
          contradicts … その仮説を否定する
          context     … 関係はあるが、判定には効かない
note      なぜ支持／反証になるのかを1文で
```

**向きが無いと、反証が残りません。** どちらの向きの事実も同じ列に並ぶと、
読んだ人には「根拠がたくさんある」としか見えません。

`context` があるのは、**判定に効かない事実を捨てさせないため**です。捨て先が
無いと、効かない事実を無理に `supports` に入れることになります。

判定と向きは噛み合っている必要があります（機械が検算します）。

- `SUPPORTED` / `PARTIALLY_SUPPORTED` … `supports` が 1 つ以上
- `CONTRADICTED` … `contradicts` が 1 つ以上
- `SUPPORTED` なのに `contradicts` がある → 通りません。
  `PARTIALLY_SUPPORTED` か `UNCERTAIN` のどちらかです

## 規則

- `external_facts[].source_url` は、**検索結果に実際に出てきた URL** だけ。
  下に「今回の検索で取得した URL」の一覧を付けてあります。この一覧に無い URL を
  書くと、その事実は保存されずにジョブごと失敗します。
- `pattern_id` は入力の PATTERN の id（P001 など）。他の値を書かない。
- `hypotheses[].evidence_links` に、根拠にした外部事実を**向きつきで**書く。
  `UNCERTAIN` 以外は 1 つ以上。`evidence`（id だけの並び）にも同じ id を
  入れてください——古い読み手のための欄です。
- **反証された仮説（CONTRADICTED）は必ず残してください。** 調べて違ったことは、
  調べていないこととは別の情報です。
- **答えの出なかった仮説（UNCERTAIN）も残してください。** 消すと、次に何を
  確かめればよいかが分からなくなります。
- `confidence` は情報源の質で決めます。
  high = 一次資料（官公庁・政府統計）に明記されている
  medium = 公的資料からの読み取り、または複数の情報源が一致
  low = 企業・ニュース・その他の単独出典
- 調査結果に書かれていないことを補わないでください。空欄のままで構いません。
